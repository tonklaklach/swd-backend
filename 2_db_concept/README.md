# Database Concept

## ACID

ACID คือหลักการที่ช่วยให้การทำ transaction มีความถูกต้องและเชื่อถือได้ โดยแต่ละตัวมีความหมายดังนี้

**Atomicity** คือการทำงานให้สำเร็จทั้งชุด หรือยกเลิกทั้งชุด เช่น การแก้ข้อมูลครูพร้อมเปลี่ยนห้องที่สอน ถ้าแก้ชื่อสำเร็จ แต่บันทึกห้องใหม่ไม่สำเร็จ ก็ต้อง rollback เพื่อให้ข้อมูลกลับไปเป็นชุดเดิม

**Consistency** คือข้อมูลต้องยังถูกต้องตามกฎที่กำหนดไว้หลังจบ transaction เช่น นักเรียนต้องอ้างอิงห้องเรียนที่มีอยู่จริง หรือห้องเรียนในโรงเรียนเดียวกันต้องไม่มีชั้นปีและทับซ้ำกัน กฎเหล่านี้ควรมี foreign key และ unique constraint ช่วยบังคับในฐานข้อมูลด้วย

**Isolation** คือการควบคุม transaction ที่ทำงานพร้อมกัน เพื่อให้แต่ละงานเห็นข้อมูลตามระดับ isolation ที่เลือก เช่น ตอนดึงจำนวนห้อง ครู และนักเรียนของโรงเรียน ทั้งสามจำนวนควรมาจากข้อมูลชุดเดียวกัน ในโปรเจกต์นี้จึงอ่านภายใน transaction เดียวกัน

**Durability** คือเมื่อ commit สำเร็จแล้ว ข้อมูลต้องถูกบันทึกไว้และเรียกกลับมาใช้ได้หลังระบบเริ่มทำงานใหม่ ทั้งนี้ยังขึ้นกับการตั้งค่าฐานข้อมูลและระบบจัดเก็บด้วย การสำรองข้อมูลจึงยังจำเป็นสำหรับกรณีที่ไฟล์หรืออุปกรณ์เสียหาย

ฐานข้อมูลดูแลการ commit, rollback, isolation และ constraints ที่เรากำหนด ส่วนแอปพลิเคชันต้องเลือกให้ถูกว่าคำสั่งไหนควรอยู่ใน transaction เดียวกัน รวมถึงตรวจ input และกฎธุรกิจให้ครบ ถ้าลืมครอบบางคำสั่งไว้ด้วย transaction ฐานข้อมูลก็ไม่สามารถรู้ได้เองว่าคำสั่งเหล่านั้นต้องสำเร็จพร้อมกัน

อีกกรณีที่ต้องระวังคืองานที่เรียกระบบภายนอก เช่น ส่งอีเมล การ rollback ฐานข้อมูลไม่สามารถดึงอีเมลที่ส่งไปแล้วกลับมาได้ จึงต้องจัดลำดับงานและวิธี retry ให้เหมาะสม

## Indexing

Index ช่วยให้ฐานข้อมูลค้นหาข้อมูลได้เร็วขึ้น โดยเฉพาะคอลัมน์ที่ใช้ใน WHERE, JOIN หรือ ORDER BY บ่อย ๆ เช่น การหานักเรียนทั้งหมดในห้องเดียวกัน การมี index ที่ classroom_id จะช่วยลดจำนวนข้อมูลที่ต้องอ่าน

ข้อดีอีกอย่างคือ unique index ช่วยป้องกันข้อมูลซ้ำได้ด้วย ในโปรเจกต์นี้ใช้กับ (school_id, year, section) เพื่อป้องกันการสร้างห้องชั้นปีและทับเดียวกันซ้ำในโรงเรียนเดียวกัน

ข้อแลกเปลี่ยนคือ index ใช้พื้นที่เพิ่ม และทำให้การเพิ่ม แก้ไข หรือลบข้อมูลมีงานเพิ่มขึ้น เพราะต้องอัปเดต index ไปพร้อมกันด้วย จึงควรเลือกจาก query ที่ใช้งานจริง และตรวจด้วย EXPLAIN QUERY PLAN ว่าฐานข้อมูลใช้ index ที่สร้างไว้หรือไม่

สำหรับโปรเจกต์นี้มี index บน students.classroom_id และ teacher_classrooms.classroom_id ส่วน unique index ของห้องเรียนเริ่มด้วย school_id จึงใช้ช่วยค้นหาห้องตามโรงเรียนได้อยู่แล้ว

ลำดับคอลัมน์ใน index ก็มีผล เช่น index (school_id, year, section) เหมาะกับการค้นหาจาก school_id หรือ school_id ร่วมกับ year ส่วน query ที่ค้นหาเฉพาะ section อาจไม่ได้ประโยชน์เท่ากัน นอกจากนี้การค้นหาชื่อแบบ substring ผ่าน instr(lower(...)) ในงานนี้ยังต้องตรวจข้อความในแต่ละรายการ การเพิ่ม index ชื่อแบบทั่วไปจึงไม่ได้ช่วยให้ query รูปแบบนี้เร็วขึ้นโดยตรง
